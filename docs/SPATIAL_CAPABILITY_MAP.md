# Spatial Capability Map

The apartment is a capability-oriented interface. Entering a room can change the set of capabilities offered by its objects.

## Kitchen

The kitchen is a gateway to food and household provisioning.

Visible objects may include:

- refrigerator — food, groceries and saved shopping lists;
- oven — cooking/media recipes;
- table — meal planning;
- phone — delivery tracking;
- menu board — cafes and restaurants;
- pantry — household goods.

Entering the kitchen may open a contextual **Food & Delivery** capability surface.

The spatial world remains visible behind it. The capability surface is contextual, not a replacement for the apartment.

## Food & Delivery

The user can choose:

- cafe;
- restaurant;
- grocery store;
- household delivery.

The system should use a verified external commerce/delivery connector when one exists. The eWorld client must not invent availability, prices, delivery times or order confirmation.

## Future rooms

### Living room

- television → video;
- music player → music;
- bookshelf → books;
- friends/avatar presence → social interaction.

### Study

- laptop → Eugene Messenger, social network and work tools;
- desk → tasks and projects;
- bookshelf → knowledge/media.

### Bedroom

- wardrobe → avatar appearance;
- mirror → appearance preview;
- bedside device → personal notifications/settings.

### Workshop

- furniture editor;
- apartment customization;
- inventory placement.

## Principle

A room is not merely a visual background. It provides a semantic context for capabilities.

**Entering a space can reveal what can be done there.**

## Safety

Location in the virtual apartment must not itself authorize consequential external actions. Ordering food requires explicit user confirmation and a verified commerce integration.
