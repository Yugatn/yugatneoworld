# СТСеть × YUGATNEO MATRIX — архитектура интеграции v0.1

Статус: проектная спецификация; функции ниже не следует считать реализованными.

## Миссия
Добровольная социально-трудовая сеть с двумя интерфейсами: классический портал труда и навигационный 2D-мир Yugatn eWorld. Цель — снизить информационную асимметрию, улучшить условия труда и предоставить пространство для образования, культуры и сотрудничества. Принципы: достоинство субъекта, право выхода, минимизация необратимого вреда, прозрачность и проверяемость.

## Два режима
1. **Труд**: вакансии, поиск кандидатов, проверяемые компетенции, договорённости, портфолио, взаимные отзывы, предложения по улучшению условий труда.
2. **Мир**: аватары, публичные и частные комнаты, гости, чат, музыка с соблюдением авторских прав, образовательные мероприятия, офисы организаций, ярмарки вакансий и творческие проекты.
Единый identity-service с раздельными настройками видимости; доступ к базовому поиску работы без обязательного участия в 2D-мире.

## Репутация, а не социальный балл
Никакого единого рейтинга гражданина и ранжирования человеческой ценности. Независимые контекстные индикаторы: надёжность договорённостей, подтверждённые навыки, условия труда, своевременность оплаты, качество коммуникации, разрешение споров. Не оценивать политические убеждения, мировоззрение, социальное происхождение, здоровье и частную жизнь.
Отзыв связан с проверяемым взаимодействием; разрешены анонимность перед публикой и конфиденциальная проверка модератором. Двустороннее право ответа, обжалования, исправления ошибок. Новые участники получают «недостаточно данных», а не низкий балл.
Показатель рассчитывается по конкретной области, с размером выборки и интервалом неопределённости. Пример: доля своевременных выплат = подтверждённые своевременные выплаты / все подтверждённые выплаты; публиковать только при достаточном числе наблюдений и защите конфиденциальности.
Не применять автоматические ограничения прав по рейтингу. Санкции за доказанные нарушения — только соразмерные, с человеческой проверкой, уведомлением и апелляцией.

## Мотивация работодателей и работников
Работодателям: видимость подтверждённо хороших условий, более качественные отклики, аналитика удержания и прозрачная процедура устранения нарушений.
Работникам: переносимое портфолио, верификация навыков, отзывы по завершённым задачам, обучение и доступ к вакансиям без покупки репутации.
Предусмотреть независимую проверку, защиту информаторов и запрет ответных мер за добросовестные жалобы.

## Архитектура
На первом этапе — модульный монолит: TypeScript frontend (портал + существующий 2D-клиент), API backend, PostgreSQL, Redis для сессий/очередей, S3-совместимое объектное хранилище, WebSocket gateway для присутствия и комнат.
Модули: identity/consent, profiles, organizations, vacancies/applications, skills, verified-interactions, reviews/disputes, reputation, world/rooms, events/learning, notifications, moderation/audit, export.
API с версионированием /v1; event ledger для подтверждений и решений; запрет хранения лишних персональных данных в публичном ledger. Разделить идентификацию и псевдоним 2D-мира.
RBAC + проверка владения ресурсом, MFA для работодателей/модераторов, rate limits, антиспам, журнал доступа, резервные копии с тестами восстановления, шифрование, удаление и экспорт данных. Для ЕС: оценка GDPR/DPIA и применимости AI Act до внедрения автоматизированного скоринга в сфере труда.

## Сущности
User, IdentityVerification, Profile, Organization, Membership, Vacancy, Application, Skill, Evidence, WorkEngagement, Review, ReviewResponse, Dispute, ReputationMetric, Room, RoomPermission, Event, Enrollment, ModerationCase, AuditEvent, ConsentRecord.
Каждая запись: id, created_at, updated_at; приватные данные отделены от публичных.

## План реализации
P0: аудит существующего eWorld, тесты и карта текущих API; спецификация приватности.
P1: профиль, организация, вакансии, отклики, фильтры и безопасные права доступа.
P2: подтверждённые взаимодействия, двусторонние отзывы, ответы и апелляции.
P3: прозрачные отдельные метрики с тестами на накрутку и дискриминационные эффекты.
P4: переход из вакансии в виртуальный офис, приглашения в комнаты, мероприятия, обучение.
P5: пилот с добровольными участниками, измерение качества подбора, споров и доверия; внешняя проверка.
Не объединять production базы без миграционного плана и согласия пользователей.

## Метрики успеха
Доля вакансий с достоверными условиями; время до подходящего трудоустройства; доля подтверждённых выплат вовремя; доля успешно разрешённых споров; удержание добровольных участников; жалобы на несправедливые оценки; доля доступных функций для слабых устройств. Проверять нежелательные эффекты, а не только рост активности.

## Связь репозиториев
Yugatn/yugatneoworld — существующий 2D-клиент и игровая социальная среда.
Yugatn/solidarnost — кандидат на самостоятельный трудовой домен; перед реализацией проверить его содержимое и согласовать границы.
Эта спецификация — точка синхронизации, а не утверждение, что интеграция уже готова.
